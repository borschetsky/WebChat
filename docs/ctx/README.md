# Context notes

Durable notes about explorations of, and changes to, this repository — what was learned,
what was decided, and why. Newest first.

New notes are written by the `ctx` skill (`.claude/skills/ctx/SKILL.md`); read that before
adding one by hand so the format stays consistent.

> **Starting cold? Read [ORIENTATION.md](ORIENTATION.md) first.** It maps the repo — what

> load-bearing, and the traps ranked by how much time each has cost — then points here for
> the reasoning behind each decision. The notes below are organised by date; ORIENTATION is
> organised by *what you are about to touch*.

| 2026-08-06 | [Client lint and format: oxlint + Prettier](2026-08-06-client-lint-and-format.md) | change | The client had no linter and no formatter, and ESLint turned out to be unavailable rather than merely unfashionable: `typescript-eslint` refuses TypeScript 7, which the client runs, so it would have left 41 of 61 files unparsed. oxlint brings its own parser and hosts `eslint-plugin-react-hooks` via its (alpha) `jsPlugins` bridge, which is the only source of the React Compiler rules — and those matter most in the 20 `.js`/`.jsx` files, where `checkJs: false` means `tsc` checks nothing at all. Landed as errors, not a warning ratchet: 20 findings, all resolved in one sitting. Four are suppressed at the site with reasons — three `set-state-in-effect` cases whose real fix is a `key` at the call site in `ChatApp` (deferred, one of them being the effect behind the old request loop), and one false positive. `jsx-a11y/no-autofocus` is off deliberately. Two things the research did not predict: **Prettier's reflow silently broke an `oxlint-disable-next-line`** by expanding a one-liner into a block and moving the offending statement away from the directive, and **Prettier needed two passes** on a method chain in `smoke.test.tsx` before `--check` agreed with `--write`. Verified: `npm run verify` green, 61/61 tests, vite build succeeds, and the react-hooks bridge proved live by linting a deliberate violation rather than trusting an empty output. Nothing runs the linter automatically yet — the pre-commit hook lives on an unmerged branch and there is no CI. |
| 2026-08-05 | [Email activation (issue #25)](2026-08-05-email-activation.md) | change | New confirm-your-email flow: 256-bit tokens (only a SHA-256 hash stored, constant-time compare, base64url), a migration that must backfill `EmailConfirmed = true` for existing rows or lock everyone out, login gated on confirmation, and two-layer rate limiting (per-IP window + per-address cooldown) that depends on `UseForwardedHeaders` running first. Brevo chosen over Resend for not requiring a domain — but the first real send landed in Gmail spam because no relay can pass SPF/DKIM/DMARC for a `gmail.com` From address, making the custom domain (#18) a prerequisite, not a nicety. Sending built on MailKit/plain SMTP so the provider is swappable via config. Verified end to end against the running compose stack with the logging sender, plus one real Brevo send; client screens verified only by typecheck/unit tests, never driven in a real browser; not deployed. |
| 2026-08-04 | [Directory-search infinite request loop in ComposeDialog](2026-08-04-compose-search-render-loop.md) | change | `ComposeDialog`'s search effect depended on the `onSearch` prop, and `ChatApp` passed an inline arrow around an RTK Query lazy trigger whose call re-rendered the parent — each search re-ran the effect, which searched again, forever, while each run's cleanup discarded the in-flight result so nothing ever rendered. Fixed at both ends: `ChatApp` memoises the callback with `useCallback`, and `ComposeDialog` holds it in a ref so it's no longer only as stable as its caller. Regression test needed a re-rendering parent harness to actually reproduce the bug — confirmed to fail (2/4) against the pre-fix code. Fix not yet deployed; production still runs the buggy commit. |
| 2026-08-04 | [Making WebChat actually deployable: compose fixes, a missing SPA build, and runtime secrets](2026-08-04-deployable-docker-and-secrets.md) | change | Postgres 18's data-dir move, Vite's Host-header check, and a wrong dev-proxy target broke `docker compose up`; fixed. The real blocker: `dotnet publish` never ran `vite build`, so every deploy would have shipped a client-less app — new `BuildSpa`/`IncludeSpaOutput` MSBuild targets fix it and fail the build if `dist` ends up empty. Found and fixed a TLS-terminating-proxy infinite-redirect via `UseForwardedHeaders`, opt-in and off by default. Secrets moved to runtime env-var injection (`.env` + `${NAME:?msg}`) instead of build-time substitution, with `ValidateRequiredConfiguration` failing fast outside Development; JWT key and DB password remain compromised in git history pending rotation, deliberately deferred to CI/CD. Verified through a full compose stack and a simulated-proxy Production build; actual DigitalOcean deployment not yet attempted. |
| 2026-08-03 | [Cloudflare R2 avatar storage behind presigned redirects](2026-08-03-r2-avatar-storage.md) | change | Avatars move off container-local `wwwroot/images` (wiped on App Platform deploys) to R2, chosen over DO Spaces for its free tier. `GET /images/{fileName}` 302s to a freshly-signed URL each request rather than embedding presigned URLs in payloads, so expiry never reaches the client and the SPA needed zero changes. Falls back to local disk when R2 credentials are absent. Fixes two pre-existing bugs (extension trusted from upload filename → stored-XSS vector; missing `wwwroot/images` directory outside Docker → exception text saved as avatar filename). **Update:** uploads are now downscaled to 256px/re-encoded/EXIF-stripped and capped at 5 MB (ImageSharp pinned to 3.1.x — 4.0 needs a paid licence); fixed a data-corruption bug where a rejected upload stored the error text as the avatar filename and returned 200; fixed a Vite dev-proxy gap that served `index.html` for avatar requests; moved R2 credentials from user secrets to a gitignored `appsettings.Secrets.json`. Upload path now verified end to end through the real UI. |
