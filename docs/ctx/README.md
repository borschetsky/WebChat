| 2026-08-03 | [Cloudflare R2 avatar storage behind presigned redirects](2026-08-03-r2-avatar-storage.md) | change | Avatars move off container-local `wwwroot/images` (wiped on App Platform deploys) to R2, chosen over DO Spaces for its free tier. `GET /images/{fileName}` 302s to a freshly-signed URL each request rather than embedding presigned URLs in payloads, so expiry never reaches the client and the SPA needed zero changes. Falls back to local disk when R2 credentials are absent. Fixes two pre-existing bugs (extension trusted from upload filename → stored-XSS vector; missing `wwwroot/images` directory outside Docker → exception text saved as avatar filename). Storage layer and read redirect verified live; upload path not yet driven through the UI. |

Optimistic send with retry; a module-scope hydration bug fixed via the first rendered smoke tests. Forced the service layer to TypeScript. Phase 5: the Phase-1 `React.memo` on `MessageRow` was inert until callbacks were stabilised with `useCallback`; `ThreadListItem` extracted and memoized; message list virtualized above 200 messages with `react-virtuoso`; a render-counting test proves keystrokes no longer re-render the list. Phase 6 (final): 5→56 tests across 6 files — reducer/selector coverage proving cross-slice isolation while typing, DTO-adapter fixtures pinning `oponentVM`/`"No messages"`/day-sorting, a date-formatting regression suite for a real day-of-month bug, and a `theme.d.ts` MUI augmentation plus a drift test guarding the `Stack` prop-dropping bug class. Live hub round trip still unverified — the one risk that survived all 7 phases. |
