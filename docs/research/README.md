# Research notes

Answers to open questions that needed facts from outside this repository — providers,
protocols, pricing, standards, libraries. Newest first.

Written by the **`researcher`** agent (`.claude/agents/researcher.md`). Give it a question
and the constraints that matter; it does the searching and writes the note.

These are **not** the same as [`../ctx/`](../ctx/README.md). A ctx note records what was done
to this repository and why. A research note records what is true of the world outside it, on
the day it was checked — so unlike ctx notes, **these expire**. Prices, free-tier limits and
library versions all rot. Every note carries the date it was verified; treat anything old as
a starting point rather than a fact.

| 2026-08-10 | [Admin console: charting licences and client-error ingestion](2026-08-10-admin-console-charts-and-client-errors.md) | What does the admin console in the new design handoff cost us in dependencies and licences, and how should client-error ingestion be built? | **Hand-roll the charts (`d3-scale` + `d3-shape`, ISC, +10 kB gz); wire Sentry rather than building `/api/client-errors`.** `@mui/x-charts` 9.11.1 is MIT and its bar chart *and* sparkline are free — but **`FunnelChart` ships only in `@mui/x-charts-pro`**, commercial at **$299/yr/dev**, no free tier for personal projects. Once the funnel is hand-drawn anyway, a library is poor value: measured locally, `@mui/x-charts` costs **+100 kB gzip to draw one sparkline** (fixed engine cost — adding the bar chart only reaches +110), Recharts +97.5, own SVG **+10.0**. On errors, two repo facts make the spec's `fingerprint` uncomputable in production: `dist` ships **no sourcemaps** by deliberate decision, and Vite 8's minifier renames `AdminOverviewCard` to `t` (verified by building it), so `componentStack` is single letters that churn every deploy. Sentry's free plan (5 k errors/mo, 30-day retention, one user) does it for $0, and its issues API returns `count`, `userCount`, `culprit`, `lastSeen` and **`stats["14d"]` — the spec's sparkline, precomputed** — so build the screen against that API and skip ingestion, grouping and retention against a **512 MB** database. If you hand-roll anyway: pass literal boundary names rather than parsing `componentStack` (`captureOwnerStack` is `undefined` in production), never put hashed filenames in the fingerprint, and use `fetch(keepalive)` not `sendBeacon` — the latter cannot carry the `Authorization` header. **Audit log:** EF Core temporal tables are SQL-Server-only, and Audit.NET audits entity diffs rather than business events — own append-only table with a `BEFORE UPDATE OR DELETE` trigger. **Invitations:** "extend" should rotate *and* re-send, which collapses it into "resend". |
| 2026-08-09 | [Redux slices vs. local component state](2026-08-09-redux-slices-vs-local-state.md) | How much of "RTK Query everywhere, all state in slices, no local state, no plain functions" should the client adopt, and which parts does Redux's own documentation contradict? | **Adopt two of the four asks; reject "no local state" and "no plain functions".** Redux's Style Guide contains a Priority B rule written to refute "all state in Redux" (*"This phrasing has been over-interpreted"*), a Priority C rule *Avoid Putting Form State In Redux*, and a Priority A rule that `Composer.anchor`/`ThreadList.bell` (both `HTMLElement`) would violate. The endorsed part — *"we recommend against writing data fetching logic by hand in almost all cases"* — is the unfinished part: `ComposeDialog` hand-rolls a search `chatApi` already exposes, and 11 auth/settings flags duplicate `useMutation`'s `isLoading`/`isSuccess`/`isError`. Those 13 disappear into RTK Query's cache, which **is** store state. The `fakeBaseQuery`+`queryFn` seam is a documented pattern, not a workaround; its four real costs are enumerated (`retry` cannot fire — verified from source, undocumented). RTK Query's **own** auth example keeps the login form in `React.useState`. React Compiler is **not** in this build, so auto-memoisation cannot offset the 18 selector sweeps per keystroke that lifting form state would add. |
| 2026-08-07 | [Unit-testing a SignalR Hub](2026-08-07-signalr-hub-unit-testing.md) | How should `ChatHub` be unit-tested on .NET 10 with xUnit, and what should `WebChat.Tests` adopt? | **Assert on `IClientProxy.SendCoreAsync`, never `SendAsync`** — `SendAsync` is a static extension, so no mock can see it, and `Received().SendAsync(...)` fails at runtime *even with the identical payload instance* because the extension allocates a fresh `object?[]` each call. Add **NSubstitute 6.0.0 + NSubstitute.Analyzers.CSharp 1.0.17** to the existing `WebChat.Tests` (the analyzer turns that mistake into a build error); hand-write `HubCallerContext`; keep plain `Assert` and xUnit v2. Moq is out for being 23 months stale, not for SponsorLink. The payload is an anonymous type — `internal`, so reflection only and `dynamic` throws; give it a name. Verified by compiling and running the tests. |

| 2026-08-05 | [Browser E2EE library for 1:1 threads](2026-08-05-browser-e2ee-library.md) | Which crypto library gives the browser client Signal-style 1:1 E2EE, and does a maintained browser-capable one exist? | **vodozemac 0.10.x compiled to WASM** — Apache-2.0, audited, ~184 KB gzipped, build the bindings yourself. libsignal is out: Node-native, AGPL-3.0, and Signal has refused to maintain a browser target.
